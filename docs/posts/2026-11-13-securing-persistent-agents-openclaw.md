OpenAI 11 月 12 日发了一篇工程实践：公司里已经有超过 500 个 OpenClaw 常驻 agent，会主动根据产品反馈开 PR、持续跑实验，不必等人下一句指令。常驻 agent 和普通 Codex 会话不一样——没有固定目标、可以 24 小时跑、也不必等人盯着每一步，还能自己改配置、写任意代码。传统软件多半防外部打进来；这里更麻烦的是，agent 自己做出偏离预期的动作。

文章写的是他们为了把这件事跑起来，实际加了哪些控制。可以立刻用上的有五条：控制面和执行面分开；硬边界先写死，再谈模型判断；用第二个模型挡一层审批疲劳；每个 agent 要有自己的身份，不能借用用户凭证；日志全记，但访问权限要收得很紧。

## 控制面是可信代码，执行面当不可信

他们把网络、身份、沙箱策略这类确定性行为，当作可信的静态代码；把 agent、它跑的环境、以及它写出来的代码，一律当不可信。为了把这条线划清楚，他们在开源项目里做了远程 harness 执行：Gateway（负责配置 agent）和 harness（真正执行）拆到不同容器；他们自己的部署里，还拆到了不同集群。

网关可以按写死的策略配置 agent；真正干活的那一侧，只在沙箱里跑。两边共容器，这条线就没了。

## 硬边界：网络、工作区、进程、密钥

沙箱管四件事：

- 网络：走组织统一的允许名单，并对明确禁止的地址再加拒绝，包括 pastebin、webhook.site，以及云 metadata 地址。
- 工作区：只允许写 agent 自己的工作目录。
- 进程：用 Codex 的 Linux sandbox 做进程隔离。
- 密钥：经 credential broker 发放，不让 agent 直接看见密钥本身。

配置上也收得比较死：关掉 `danger-full-access`；网页搜索只走缓存索引，不开放实时外搜；强制走托管网络代理，而且用户级配置不能自行扩大域名允许名单。环境变量里的 `GH_TOKEN`、`GITHUB_TOKEN` 一类默认过滤掉；应用默认关闭，破坏性操作和开放世界操作也默认关。

这些都是确定的策略，不靠模型临时决定「这次能不能碰」。

## Auto-review 用来省人的注意力，不能代替硬边界

静态控制不会跟着模型变强而变强。他们的补法是 Auto-review：用第二个模型盯着主 agent 的动作并做批准。每一步都拉人点同意，人很快会习惯性全过。模型先过滤一轮，人只处理高价值审批。OpenClaw 和 Codex 都原生支持这个能力；他们的内部部署对所有 agent 动作都开了自动审查。

原文没有给出审查命中率，也没有说漏过了多少不该过的动作。模型审查是过滤器，不是可以放开沙箱的理由。

## 身份要拆开，审计和关停才做得到

一次动作是用户发起的，还是 agent 自己发起的，必须分得清。他们把 agent 身份和用户身份分开：agent 用自己的身份访问资源，需要代理用户时再走 OAuth 委托。文中提到两个还在形成的规范：WAG 给 agent 自己的资源访问，XAA 让 agent 经 OAuth 代用户行事。agent 身份也不是服务账号；两者要一起用——agent 以自己的身份行动，访问第三方时走挂在该身份下的服务账号。

他们的做法是：每个 OpenClaw agent 都有独立身份，并绑到一个 ChatGPT Service Account，推理凭证和用户的分开。这样可以给 agent 接自定义插件，也可以按 agent 审计，必要时单独关掉它的推理，而不必收回用户本人的权限。

## 全记日志，但只给少数人看

控制面的每一次配置变更，以及 agent 的每一个 turn，都要记下。常驻 agent 出了偏离，靠这条链路才能回溯。turn 日志里常有敏感内容，所以访问锁得很死，只有安全组里少数几个人能看。

文末还提到，Dev Day 上公布的 OpenClaw Enterprise（OCE）是一个开源、不绑厂商的 agent 控制面，用标准 Codex preset 就能带上不少上述防护。项目仍在试点，计划年内到 1.0。

## 可立刻落到自己仓的五点

1. 配置、网络、身份、沙箱策略放在控制面，和 harness、agent 写的代码、它跑的环境分开部署。网关不要和执行面共容器。
2. 先写死硬边界：网络允许名单加明确拒绝（务必包含云 metadata）；工作区只许写自己的目录；进程隔离；密钥走 broker，也不要把密钥放进环境变量。原文提醒，只过滤环境变量藏不住文件里的凭据，所以工作区外的密钥文件也要挡住。关掉 `danger-full-access` 这类放开开关，并且不要让用户配置扩大允许名单。
3. 人审每一个动作会疲劳。用第二个模型做 Auto-review，人只看高风险审批。模型审查不能代替硬边界；上线前要自己测漏过率，原文没有给这个数字。
4. 给每个 agent 独立身份和推理凭证，不要借用用户 token。需要审计或关停时，能单独关掉这一个 agent。
5. 控制面变更和每次 turn 都记日志；日志可能含敏感内容，访问范围要收紧。
