OpenAI 11 月 2 日发了一篇工程文：Codex 让工程师同时开出更多分支、推得更勤，CI 和研究任务也会跟着去拉同一份提交。大约从去年年底起，他们的 monorepo 开始出现推送和拉取变慢、合并失败，可靠性有时掉到 90% 以下。

版本控制系统和日常 Git 用法都保持原样。他们重做了服务端，做成兼容 Git 协议的后端 Pando。文里写，上线后中位推送时延大约降到原来的五分之一，每天能送出接近 1 PB 的 Git 数据。

前几篇写的是长跑 agent 怎么把会话和班次接上。这篇落到再往下一层：许多编码 agent 同时写同一个仓时，先顶不住的往往是源码服务。

## 卡住的是怎么服务 Git

文里把负载拆成两边：许多客户端同时往不同分支推，以及许多客户端同时来拉同一段历史。传统做法很难两边一起撑住。

他们比较了两类常见架构。三阶段提交要在副本之间就一次引用更新凑齐多数票，引用只能一个一个改，磁盘和网络往返都压在推送路径上。基于预写日志的做法可以把 pack 并行上传，但发布时仍要改一份全仓共享的清单，无关分支的推送也会挤在同一个比较并交换上。

Pando 放下了两件许多 Git 服务默认要守的约束。一是整个仓库在某一时刻对齐：要给所有引用一张同一时刻的快照，就得在全仓范围内协调，无关分支也会互相堵住。二是为每个客户端单独打一份 pack：两人本地历史不同，服务器就可能各算一套，CPU 和磁盘很快被拉满。

## 分支各自串行，跨分支可以并行

推到某一条分支时，Pando 把 pack 写成不可变对象，再记下这条引用的新版本、这个 pack，以及它依赖的更早版本。对象存储和元数据存储都可以横向加机器。只有推同一条引用才会冲突；推到无关分支的请求，可以由不同的服务端并行收下。

代价是：连续读几条分支时，不能假定它们描述的是仓库里同一个时刻。文里的判断是，人和 agent 真正依赖的是单条引用上的顺序，而不是全仓更新的全局次序。

推新功能分支时，Pando 默认只向客户端宣告一条主干，让对方按主干来打包。宣告的引用不会随着分支变多而膨胀；已经有主干历史的人，用这一个 pack 就能取到这条分支。往后同一条功能分支再推，或把分支叠在另一条功能分支上，客户端可能把主干以外的对象再传一遍，包会变大。他们在自己的 monorepo 里权衡过：这样打出来的 pack，中位数不到 20 KiB，99 分位不到 3 MiB，可以接受。

## 推上去的 pack，直接给后来的人用

常规 Git 服务会根据客户端声明的 have / want 现算一份差量 pack，这种结果很难缓存。Pando 在推送时就记下 pack 和依赖，拉取时把 have / want 映射成一组已有的引用版本，把现成的 pack 交给客户端。

Git 的 HTTP 响应里通常只能内嵌一份 pack。他们用了协议里较少被提到的 `packfile-uri`，把真正的包放到链接上另下，并给上游提交了并发下载、中断清理、续传校验等相关修补。文里还写，按提交或按包做本地缓存后，命中率超过 99%，单小时送出过 57 TB 的 pack，克隆和拉取能把 10 Gbps 的网卡跑满。

主干一天可能累积成千上万个小 pack，不能按推送次数一个一个拉。他们在后台按类似 LSM-tree 的方式，把小 pack 合成跨越多版引用的更大一层，既提高压缩，也让拉取规划能按对数时间跳过中间版本。

## 十周上线，先当代理再切流量

Pando 从立项到生产大约十周。核心设计是一名工程师，实现主要靠多组 agent，部署由少数工程师收尾，今年 4 月开始接生产流量。实现用 Rust，并配了对照标准 Git 行为的测试套件，以及确定性模拟，用来抓协商和打 pack 时的竞态。后来他们还让 GPT-6 Astra 驱动的 agent 用 Lean 和 TLA+ 写「Pando 的理论」，连续跑上百小时找边角问题，并安排 agent 全天候做红队。

上线时先做现有系统的读写代理，两边保持同步，再按工作负载切流量。他们写了迁移用的 skill，开发者可以直接让 Codex 改自己的环境和检出。文里把中位推送时延的下降写成大约 80%，和开头「接近 5 倍」是同一组口径。

## 可立刻落到自己仓的四点

1. 编码 agent 一多，先看推送时延、合并成功率，以及 CI 同时来拉同一提交时服务端会不会被挤满。这不一定说明 Git 本身到了上限，更常见的是服务 Git 的方式没跟上并发。
2. 人和 agent 通常只依赖单条分支上的顺序。如果自己在搭或评估源码服务，先问仓库级同一时刻对齐是不是真的必要——它会让无关分支互相等待。
3. 许多 agent 和 CI 会反复拉取同一段历史。能复用已经生成的 pack，比按客户端现算一份更扛得住读放大。
4. 切换后端时先做代理，并用 skill 让编码 agent 自己改检出和环境。并发一高，要把 Git 兼容性和竞态写进 agent 能跑的测试里，不能只靠手工用例。
