本地编码 agent 有个老矛盾：每一步都点同意会累，关掉权限又太野。Anthropic 给 Claude Code 加的 auto mode，走的是第三条路——把一部分审批交给分类器，专门拦「模型太积极、越界动手」的那种动作。

背景数字很实在：用户大约批准了 93% 的权限提示。点多了就会走神。沙箱安全但要持续配；`--dangerously-skip-permissions` 零摩擦也零保护。中间那条人工审批，实际里多数时候已经被习惯性点掉了。

## 两类失败，同一道闸

他们内部事故日志里常见的不是「模型故意作恶」，而是 overeager：真想帮你，但主动过了头。删远程分支、把 GitHub token 传到别的集群、对着生产库跑迁移——往往是「合理解题」用过了界。

威胁模型拆成四类：overeager、误判爆炸半径、提示注入、真正的目标错位。auto mode 的分类器主要按前两类调，但拦的是动作本身，不管动机。

文里举的会拦例子包括：模糊的「清理旧分支」演成批量删远程；鉴权失败后满盘 grep 找备用 token；「取消我的任务」却按名字相似度猜目标去删；为了调试把脚本丢到公开 Gist；部署预检失败就带上跳过校验的旗标重试。

## 输入一层、输出一层

输入侧：工具结果（读文件、抓网页、shell 输出、外部工具返回）进上下文之前，先过服务端的提示注入探针。看起来像劫持指令的，会附带警告，提醒模型回到用户原话。

输出侧：transcript classifier（Sonnet 4.6）在动作执行前当「替身审批人」。两段式——先单 token 快筛（偏拦），只有打上标记的才进第二段带推理的复核，省推理成本。分类器故意只看用户消息和工具调用，不看助手自白和工具输出：模型没法写一段「用户其实默许了」来说服它。

子 agent 交接也过闸：委派时可以否决（子会话里编排者的话会变成「用户消息」，看起来像已授权）；返回时只警告，防中途被注入污染的结果无声回流。

## 多数日常改码根本不进分类器

三层放行：

1. 内置安全工具白名单 + 用户 always-allow（读文件、搜索、导航等）。进 auto mode 时会丢掉那些等于「任意执行」的宽规则（整壳、通配解释器、包管理器 run）；窄规则可以留下。
2. 项目目录内的写文件：走 git 可审，不付分类器延迟。
3. 其余——壳命令、外网、项目外路径、子 agent——才进分类器。

策略模板固定，中间留三个可改槽：信任边界（默认只信当前 git 仓）、默认二十多条拦截类（毁坏/外泄、降安全姿态、跨信任边界、绕过评审或动别人的资源）、以及窄的允许例外。`claude auto-mode defaults` 能看到完整默认值。

## 数字怎么读

全链路在真实流量上假阳性约 0.4%；真实 overeager 样本上假阴性约 17%。他们写得很直：多数漏拦并不是没认出危险，而是把会话里「像授权」的话当成了覆盖爆炸半径的同意——「清理这个 PR」不等于允许 force-push。

和 `--dangerously-skip-permissions` 比，这是实质升级；和「每一步认真人审」比，它不是替代品。适合想少点确认、又不愿全开危险跳过的场景，不适合高风险基础设施上的仔细人工把关。

被拦之后不是停死等人：拒绝作为工具结果回来，模型被要求换更安全的路；连续拒 3 次或累计 20 次才升级给人（无头模式则直接结束进程）。所以假阳性大多只是多一次重试，长任务还能活下来。

## 对我自己搭闸门的启发

软闸（提示、约定、分类器）和硬闸（沙箱、出站、文件系统边界）要叠着看。auto mode 明确说了：它是给「本来会跳过全部审批」的人用的中间层，不是把环境边界撤掉的借口。

若你在自己的 harness 里做「替身审批」，两条设计值得抄：分类器尽量推理盲（别让助手文案自我辩护）；拒绝后继续找替代路径，而不是一拦就整条会话死亡。
