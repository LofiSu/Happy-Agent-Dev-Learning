今年 9 月，Anthropic 用专用平台 Prove2Me，加上研究员带队，花了 11 天，把费马大定理形式化进 Lean。11 月 9 日这篇写了一个对照实验：一千个跑早期 Claude Fable 5.2 的 agent，不用 Prove2Me，也没有人中途指路，只用通用工具，28.7 小时把证明再做了一遍。输出 token 大约是上次的三分之一，证明长度大约是七分之一。

值得记下的不是「模型更强了，人可以不管」，而是三件事：通用工具够不够用、共享状态怎么建、放大规模之前安全边界要先叠好。

## 协作件只有 Git 和数据库

每个 agent 在独立沙箱里，没有联网。手里的工具是 shell、编辑器、Lean 工具链，外加自己的 Git 分支和一份共享 Postgres。证明交到 main 之后，由单独的 grader 检查。

上次专用平台要解决的，正是「大家不知道项目进行到哪，开始各干各的」。这次改交给通用原语：Git 管可检查的产物，SQL 管认领、备忘和已完成记录。选 SQL 的理由很朴素——事务能扛住一千个并发写，而且模型本来就会用。

跑起来后，lead 在前 10 分钟自己建了五张表：对全队下令的 Announce、分配任务的 Assign、公开进展的 Notes、谁先领谁做的 Subtasks、已落地的 Landed。这套表结构不是人事先设计的。

## 先别把「做不到」当结论

提示词只给了 60 条待证命题、一句经典路线素描、必要定义，以及上次形式化里已经证过的 47 条引理。组织方式几乎只有一层：一个 lead、999 个 helper。harness 另外给 lead 发了 19 次剩余时间提醒，鼓励它别停。

Helper 一开始把其中 47 条判成「预算内做不完」。Lead 先集中打它认为能做的 10 条，大约 70 分钟全部证完，再写下吞吐量远高于早期判断，把人重新派到先前放弃的难题上。最难的 Langlands–Tunnell，队长曾估完成概率不到 1%；后来拆成最深 10 层、2418 个任务的树，子任务可以先假设下层成立，几百个 helper 才能并行。28.4 小时这条证完，28.7 小时主定理上 main。

可落到自己系统里的判断是：agent 会系统性低估难度，也更容易放弃。开局的「不可行」不能当最终结论；要留一个能根据已完成结果改派工的角色，而不是一开始就锁死分工。

## 放大之前，先把沙箱和监控叠上

单机大约 100 个 agent 就会在内存、磁盘或 CPU 上撑不住。一千个沙箱能跑，是因为隔离在先，协作走共享存储，而不是挤在同一台机器上互发消息。

安全不是单靠一层。每个沙箱无网，命令以非特权用户执行；agent 只能推自己的分支、开合并请求，合入 main 由沙箱外的任务做；数据库是无特权角色，语句有时限和写入上限；身份在网关侧标注，沙箱里的进程改不了。工具调用事前有分类器，跑完还有离线监控，可以回看其他 agent 的动作。分类器挡住一次，lead 被拦则整队停，helper 被拦则只移掉它，等人审完再继续，免得另一个 agent 接着做被拦住的事。

这次一百万次以上工具调用里，没有一次达到拦截线。作者也写明：这是有安全边界的玩具实验，推不出「专用 harness 可以不要」——Prove2Me 这类平台在编译效率和复用人类结果上仍然有用；人在关键节点鼓励，也能避免过早停工。

## 可立刻用上的四点

1. 多 agent 先解决共享状态：可认领的任务、可检查的产物（测试、类型检查、Lean 这类 oracle），比再开一个聊天频道有用。
2. 读和写分开权限：调查、分类的角色不要直接改主分支；合入和发布放在沙箱外，由人或独立 grader 拍板。
3. 不要把开局的难度判断写死。留一个根据已完成结果重新派工的机制，任务能再拆就再拆，做成树而不是一张平铺清单。
4. 规模上去之前先要隔离和监控：一 agent 一沙箱、无网、身份在外、工具调用可拦可审。专用平台不是必选项，但通用工具能跑，不代表它更高效。
